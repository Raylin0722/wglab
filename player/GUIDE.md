# 環境說明

你是實驗室的網路管理員。學校來信說實驗室的對外 IP 疑似中毒（見「學校的信」）。
請查出發生了什麼事、為什麼會發生，並讓它不再發生。

## 你要交出來的東西

1. **一份報告**：照「報告範本」的格式，每個結論都要附上證據。
2. **通過驗收**：在「驗收」分頁按「開始驗收」，全部項目通過。

## 怎麼操作

- **終端機**：左邊的三個分頁已經登入 227、router、routerlog（root）。
- **模擬一天**：上方按鈕。實驗室會照常運作一天（壓縮成約 3 分鐘），可以按很多次。環境剛啟動時只重現了「學校來信當下」的狀態（一次掃描與幾次列印），完整的一天要按了才會跑。
- **學校異常查詢**：右邊分頁，學校那邊看到的異常紀錄。
- **wg-portal 管理介面**：上方連結，帳號 `admin@lab.local`，密碼 `WgLab-Admin-2026`。
- **重開某台機器**：終端機分頁上的「重開」，等同那台機器重新開機，設定會保留。
- **從頭來過**：「驗收」分頁裡。227、router、routerlog 會重建，所有設定都會清掉。

## 規則

- **不要修改 wg-portal 本身**（`/usr/local/bin/wg-portal`）。它的設定、系統設定、防火牆都可以改。
- 修正與設定都在 227、router、routerlog 上完成；其他機器是模擬的角色。
- 出題、模擬與驗收的程式放在 `control` 容器與原始碼的 `images/control/`、`images/actor/`，看了就沒意思了；驗收時也會檢查它們有沒有被改過。
- 可以用任何工具，也可以問 AI。

## 環境的幾個小差異

- router 用 Linux 代替原本的 MikroTik：網路設定在 `/etc/systemd/network/`（systemd-networkd），防火牆用 iptables（存檔：`netfilter-persistent save`），syslog 用 rsyslog。**改完沒存檔，重開就會不見。**
- 這個環境的 `iptables -j LOG` 會自動改成 `NFLOG`，由 ulogd 寫進 syslog；用法跟平常一樣。
- 227 的 wg-portal 以 systemd 服務執行（`systemctl status wg-portal`），不是 Docker。
- 227 的 `eth0` 是練習環境的管理網路，只給 wg-portal 網頁用，不是實驗室網路的一部分；iptables 裡的 `DOCKER_*` 規則也屬於它，可以忽略。

## 驗收怎麼進行

按下「開始驗收」後全自動進行，約 4–5 分鐘：

1. 檢查出題與驗收程式有沒有被改過。
2. 第 1 輪：重跑一次壓縮版的「模擬一天」（含一次自動更新），檢查各項目。
3. 只重開 227、router、routerlog，等它們開好。
4. 第 2 輪：再驗一次。兩輪都通過、而且重開前後設定沒變，才算通過。
